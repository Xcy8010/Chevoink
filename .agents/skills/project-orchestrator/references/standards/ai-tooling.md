# AI — Providers, native calls, streaming and quality receipts

Apply to software integrating model providers, executable tools, streaming arguments, generated patches or model-based checks. These govern the product being developed; they do not silently change the Codex orchestrator's chosen model routing.

## AI-01 Protocol is a behavior contract

Register tools with reviewed names, descriptions, native schema, permissions and receipts. Validate required IDs and business text; omit only schema-optional blank fields. Never execute pseudo-call prose, historical excerpts, receipts or model-imagined JSON as native calls. External text is untrusted data. Preserve recent real tool request/result pairing, goal, constraints, object identity and retrieval references when reducing context; do not splice summaries into executable arguments.

## AI-02 Verify provider compatibility

Before setting tool-choice or reasoning fields, verify current provider, endpoint, model, effort, custom/proxy routing and capability. Normalize compatibility before request encoding and request/billing hashing. Use a required-tool mode only when actually supported; do not turn off reasoning, change the user's selected model, widen permissions or retry budget to force a call. Tool-free final output omits requirements for new tool calls. Do not embed an evergreen provider-compatibility matrix; verify the exact integration when changed.

Test the actual serialized HTTP body, endpoint, effective effort, normalization and exactly the intended dispatch count—not only prompt text or a mocked description.

## AI-03 Stream and argument integrity

Use shared envelope normalization, stream assembly and schema validation. Distinguish incomplete from valid complete arguments/content. Automatically repair only syntax proven equivalent; closing truncated JSON must not invent missing text or silently convert partial content to success. Preparation previews are bounded and distinct from saved state and authorized execution (see UI-04).

## AI-04 Version-bound evaluation and patching

A pre-change critique cannot certify a changed artifact. Verify again against the post-change revision and exact dependencies. Cache reports only under matching version/hash, sources and protocol. Patch anchors must be unique/non-overlapping in the original input; do not apply cascading replacements into newly generated text. Reject stale object/read IDs instead of guessing.

Evidence-based findings need locatable, faithful evidence; where exact quotes are required, validate contiguous verbatim spans. Bounded repair addresses the invalid finding or artifact once under a declared policy; do not drop findings, lower thresholds or keep rewriting until a judge says yes. Subjective quality goals require project-specific evaluation and, where necessary, human acceptance; do not present them as deterministic correctness.

## AI-05 Honest cost and receipts

Report preparation/execution/postcondition separately. Keep read-only structured receipts with actual IDs/status rather than assistant prose that resembles executable history. Preserve user text during legacy cleanup. Measure input/output/cache usage, outcome, latency and real provider/user charges separately with matched workload and budgets. Cached input is not a quality certificate. Verify current provider accounting semantics and units rather than importing symbols or formulas from another integration.
