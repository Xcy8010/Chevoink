# 32 · 作品一键导入与文档解析产品级实施方案

> 状态：待实施方案；本轮仅调查、设计与撰写文档，不代表功能已经实现、测试或上线。
>
> 日期：2026-09-13。代码基线：`583f11a300c054f22483229a1dc4dd03f3609c89`。
>
> 目标：把用户提供的文件可靠地导入**当前作品 → 卷 → 章**；原文不被 AI 改写，缺失内容不被编造，覆盖必须由用户确认，失败不得损坏现有作品。

## 1. 产品范围与不可妥协的约束

### 1.1 本次交付范围

- 创作区顶部「作品」菜单内，在「一键导出」正上方新增「一键导入」，使用上传/导入图标；Work、IDE 及移动端对应菜单进入同一个流程。
- 文件选择与拖放支持 `.zip`、`.txt`、`.md`、`.pdf`、`.doc`、`.docx`；首版一次处理一个主文件，ZIP 可包含多卷多章，不把不同作品自动合并。
- 必需内容：至少一章非空正文。可选内容：书名、封面、卷、简介、标签。
- 没有卷时创建「正文卷」；没有可识别章标题时允许把原文作为一章，由用户确认标题。不能为了满足数据结构让模型补写正文。
- 已有章节的作品必须经过两个独立的自定义覆盖确认弹窗；Agent 入口不得绕过。
- 必要时用 AI 辅助结构识别：内置基础模型、`low` 思考并按现有规则消耗额度；本次选择自定义模型时必须使用该模型。
- 提供 Agent「一键导入」工具：先解析/预览，后经用户确认提交；不允许逐章写入工具绕过批量导入授权。
- 首版完整交付须包含六种格式、扫描 PDF 的可见处理路径、预览纠错、覆盖恢复、Agent 审批与三端适配，不能只加入口后宣称完成。

### 1.2 非目标

不自动联网找书、不根据链接抓取整本书、不生成缺失章节、不自动学习 Style DNA、不自动生成记忆卡、不恢复 ZIP 中的 Agent 会话/技能/可执行指令，不自动发布作品。上传内容是待解析数据，不是对系统的指令。

正文导入不是排版复刻：需保留段落、对话、场次、标题及正文含义；不承诺 Word/PDF 字体、分页和复杂排版完全复原。正文内插图要保留可查看的附件及来源标记，不能无提示丢弃；封面另行选择。

### 2.1 对 PDF 和 Token 的直接结论

1. **目前可能识别不全。** 纯扫描 PDF 可能没有文本；混合 PDF 更隐蔽——有些页有字、有些页只有图，当前文本结果不能证明所有页均已处理。双栏、页眉页脚、特殊字体也可能导致乱序或异常文字。
2. **目前不会自动完整理解 PDF 图片。** 正文插图、扫描文字、封面需要新的图像提取/OCR 路径。不能把“未抛异常”称为完整识别。
3. **解析本身不等于消耗模型 Token。** 当前本地文本提取不调用模型；把提取文本发进对话才消耗上下文。20,000 是字符上限，不是固定 Token 数。整书反复续读、历史重复携带、逐页视觉识别都可能增加费用。
4. **改造方向：原文保留在服务端，模型只处理有歧义的局部。** 分页/分块一次解析、后续复用；OCR 按需要的页或区域做，不默认把整本书转成图片发给大模型。

## 3. MarkItDown 调研与技术选型

本轮核对上游 `main` 对应提交 `cc0ca9edd8e23b2c7f7b778c7b148c1565730498`；这不是对某个 PyPI 已发布版本的可用性保证。实施时必须锁定依赖版本/哈希、核对许可证和实测，禁止生产安装浮动 `main/latest`。

| 上游能力 | 已核对事实 | 本项目决策 |
| --- | --- | --- |
| 通用转换 | Python 工具，把多格式内容转换为 Markdown；不是作品导入产品 | 借鉴统一文档转换层，不让它承担授权、分卷分章、提交或恢复 |
| PDF 默认转换 | 所核对代码使用 pdfplumber/pdfminer 文字/结构提取，不能据此认为默认具有扫描 OCR | Node 原生文字提取优先，复杂排版可试第二解析器；必须独立维护页覆盖报告 |
| DOCX | 转换器接受 `.docx`，使用 Mammoth 转 HTML 再转 Markdown | Node 现有 Mammoth 可升级为结构化提取；「支持 Word」不能推导为旧版 DOC 已受支持 |
| ZIP | 逐成员转换再拼 Markdown；所核对代码会跳过部分不支持/转换失败的成员 | 不直接作为整包导入器；由本项目列清单、安全解包、逐文件记录成功/失败并保留路径层级 |
| OCR 插件 | 同仓库 `markitdown-ocr` 提供图片/扫描页视觉 OCR；没有客户端时会跳过 OCR，模型失败也可能继续其余转换 | 可作候选适配器，不直接采用“失败后继续但不给用户清单”的行为；费用与网络请求必须走本项目网关 |
| 云转换 | README 提供 Azure 文档智能等可选路径 | 首版不默认引入第三方云 OCR；如后续启用，必须说明数据发送对象、授权和独立费用 |

### 3.1 首版架构决策

- Node API 负责认证、上传、任务编排、模型网关、计费、预览和原子提交。
- 文本与 DOCX 使用现有 Node 依赖；Markdown 使用 AST；PDF 增加页面/块级解析适配器，不把当前截断接口改成无限返回。
- DOC 使用隔离的 LibreOffice headless 转换到 DOCX，再进入同一管线；它是**拟新增依赖**，当前仓库没有该能力。部署验收必须包含真实二进制 DOC，重命名 DOCX 不算。
- 本地 OCR 采用隔离的中文 OCR worker（候选 PaddleOCR，版本/语言包/资源消耗须在实施探针锁定）；对低质量局部再提供用户确认的视觉补识别。若 OCR worker 未通过验收，只能标记该能力未完成，不能用静默忽略扫描页代替。
- MarkItDown 作为复杂结构转换的可选 Python worker 适配器，通过同一 `ParsedDocument` 契约接入；先对比测试再启用，不为普通 TXT/MD/DOCX 强制多一次跨语言转换。
- Worker 无业务数据库权限、无供应商密钥、默认断网、非 root、只读运行环境、单任务隔离目录，限制 CPU/内存/执行时间。需要视觉补识别时返回页/区域请求，由 Node 验权和计费后调用模型，不让插件自行无限调用。

## 4. 用户交互与两次确认

### 4.1 入口与前置检查

1. 点击「一键导入」先取得当前作品真实章节数，加载失败不按空作品处理。
2. 存在本地未保存正文时先完成保存；保存失败保留草稿并阻止提交，不丢弃用户输入。弹窗与任务始终绑定启动时的 `novelId`，路由切换不得把结果写入新作品。
3. **只要已有章节（包括空白章节）**，立即弹第一层自定义提示：
   - 标题：「是否覆盖当前作品章节？」
   - 正文：「《作品名》已有 N 卷 M 章，其中 K 章有正文。导入将替换当前创作区卷章；确认前不会删除内容。」
   - 按钮：「取消」「是，继续」。默认焦点在取消，不记忆“总是允许”。
4. 点击「是，继续」弹第二层独立确认：
   - 标题：「再次确认覆盖」；列出目标作品、旧章节数量、恢复机制以及发布/待审影响。
   - 按钮：「返回」「确认并选择文件」。明确说明这里确认的是**进入覆盖导入流程**，不是此时删除旧章节。
5. 两层确认均通过后打开文件选择/拖放面板；空作品直接打开面板。取消系统文件选择器不造成写入，也不清空已选文件或预览。

两次入场确认不得充当无限期写入许可。完成解析后的「确认导入」会绑定实际文件、预览与当前作品版本；若基线变化或确认已过期，须重新展示覆盖两次确认，不能套用旧批准。这是安全校验，不是每正常导入都无意义地重复四个弹窗。

### 4.2 导入工作台

流程：`选择文件 → 检查文件 → 解析内容 → 预览与调整 → 确认导入 → 导入完成`。

- 上传区显示允许格式、大小上限、已选文件名/大小、进度、重新选择及取消。
- 桌面支持在导入面板内拖放文件；不拦截编辑器正常文字拖动，不在整个创作区任意落点直接启动覆盖。
- 预览左侧显示作品/卷/章树、章节数和字数；右侧显示选中章节原文、来源页/文件、识别警告。长列表虚拟化，正文按需加载。
- 用户可调整章名、卷名、归卷、顺序、合并/拆分边界；每次编辑更新预览版本和摘要哈希。未分配的正文进入「待归属内容」，不能自动丢弃。
- 展示现有卷章与待导入卷章的数量/字数对比，以及未处理页、被排除文件、疑似重复、可恢复范围。
- 书名/简介/标签/封面逐项显示「当前值 → 识别值」及来源；**默认保留当前元数据**，需要用户主动勾选应用。识别不到不清空，不生成凑数标签或简介。
- 卷章正文属于导入目标，不提供含糊的“自动合并旧书”；首版采用“空作品导入”或“整体替换创作区卷章”。追加导入列为后续独立模式。
- 原文中的空行和段落尽量保留；标题去重、页眉删除、断行合并等都要有可回退的转换记录。剧本场次标题与人物对白不能按小说规则强拆。
- 提交按钮为「导入 N 卷 M 章」；已有内容时为「确认覆盖并导入 N 卷 M 章」。至少一章非空正文、所有阻断问题解决后才可点。
- 成功后刷新卷章树、字数、当前编辑章节及 Work 面板，提供「查看首章」「查看导入报告」「恢复导入前版本」。Agent 回执可导航至导入章节。

### 4.3 防误触与跨端

- 上传与预览使用可恢复任务；关闭面板只是收起，不默认取消后台解析。明确区分「稍后继续」与「取消任务」。
- 未保存预览调整时离开需自定义确认；保存状态明确。刷新/重新登录后只恢复本人的当前作品任务。
- 手机采用全屏分步面板，目录与正文切换，底部操作栏适配键盘和安全区；按钮触控区域至少 44×44 CSS px，长文件名换行，禁止横向溢出。
- 两次确认不叠加显示；阻止点击穿透。危险按钮不能被上一弹窗的 Enter/连续点击触发；处理 IME composition。
- 对话框具备标题/描述关联、焦点圈定及关闭后焦点恢复；Esc/系统返回不丢预览。在原子提交阶段显示真实“正在提交”，不把收起当作取消成功。
- Web、Windows WebView2、Android 文件选择和应用返回均需验收；Android 使用可用文件选择器读取流，不依赖桌面绝对路径。拖放是增强能力，不作为手机必需操作。

## 5. 格式识别与内容完整性

### 5.1 统一中间产物

拟新增 `ParsedDocument`：`sourceId/sourceHash/parserVersion`、文件清单、页清单、结构块、图片资源、警告与转换记录。

每个块保留稳定 `blockId`、原始/规范化文本、文件成员路径、页码（适用时）、段落/字符区间、类型与识别方式。页/块状态区分 `native`、`ocr`、`needs_review`、`failed`、`excluded_by_user`、`verified_blank`。不存在页码的 TXT/MD/DOCX 使用段落位置，不伪造页码。

拟新增 `ImportManifest`：元数据候选与选择、卷章有序树、正文块引用、来源覆盖清单、待解决问题、预览版本和 `manifestHash`。模型不直接返回待写入整书，正文由服务端按照确认的来源块/边界构建。

**完整性定义：所有来源正文块都已归章，或被用户明确标记排除且记录原因；所有页/成员都有可解释结果。** 处理覆盖率与文字识别正确率是两个指标，不能用“页数全部处理”宣传 OCR 100% 准确。

### 5.2 TXT / MD

- 检查 BOM，优先严格 UTF-8；尝试 UTF-16、GB18030 等明确编码候选，利用仓库现有 `iconv-lite`。有歧义时展示样例让用户选编码；不得在充满替换字符的情况下宣告成功。
- TXT 组合识别「第 X 卷」「第 X 章/回/节」、中文/阿拉伯数字、序章/楔子/番外；不是每个正文中出现“第一章”的句子都成为标题。
- MD 解析标题层级和段落，不在代码块、引用、目录链接列表中误切章；外部图片/链接仅保留引用，不自动访问。
- 优先级：可信结构清单 → 文档显式标题/卷目录 → 连续章节编号与上下文 → 局部 AI 建议 → 人工确认。无标题原文保留成待确认单章，不总结替代。
- 字号/标题不明确的剧本按现有显式分集/场次呈现候选层级；提供「小说 / 剧本 / 保留原结构」模式，剧本不要求存在“第 X 章”才可导入。

### 5.3 ZIP

- 解包前扫描目录，验真实格式与成员类型，拒绝加密包、路径穿越、绝对路径、盘符/UNC、链接成员、大小写/Unicode 归一化冲突路径。
- 流式限制解压总量、单成员大小、成员数量、压缩比、处理时间；拒绝嵌套压缩包。DOCX 自身的 OOXML 容器按专用解析规则处理，不算用户嵌套包。
- 识别本站旧版导出结构：只从 `正文/卷目录/章节.txt` 提取正文；目录和规划不得重复导入为正文，发布建议不得当作原作品简介。TXT 文件开头重复章标题只在与文件章名一致时去一次。
- 对普通 ZIP 使用目录层级和自然数字排序（2 在 10 前），目录不能确定卷时让用户调整；多个书根目录必须明确选择一本。
- 封面只从本地图片候选中选择并安全转码；`__MACOSX` 等系统文件可按明确规则排除并在报告计数，其余不支持/失败文件逐项显示。
- 不能把“只有封面、目录、计划”的 ZIP 当成功；不能以第一份 TXT 代表整包。任何含正文可能性的失败成员会阻断默认完整导入，用户只能显式排除并接受「部分导入」标记。
- 后续可在导出 ZIP 内增加版本化 `chevoink-export-manifest.json`，记录顺序/类型/内容哈希提升往返准确性；必须兼容旧 ZIP。上传清单依然不可信，清单中的用户 ID、作品 ID、路径和摘要全部重新校验，禁止据此跨作品写入。

### 5.4 DOC / DOCX

- DOC 校验 OLE 容器，不接受仅改扩展名；在隔离 worker 通过受限转换器转 DOCX。禁用宏、外部链接更新、远程模板，设置独立用户配置目录与超时；损坏/密码保护明确报错，转换失败不覆盖原书。
- DOCX 不只调用 `extractRawText`：提取标题样式、段落、列表、表格、内嵌图片及必要文本框等；转换器无法覆盖的对象进入警告清单。
- 表格中的对白/分镜按行列顺序保留，不能扁平化后把对白角色混淆。批注/修订应识别并让用户选择最终视图，不能无提示合并删除文字。
- 图片中的正文单独 OCR，装饰图默认不送模型；保留图片查看入口。不能承诺复杂文档全保真，无法确认的块在预览中阻断或显式排除。

### 5.5 PDF

1. 预检总页数、加密/损坏、文字层、图像覆盖及页面尺寸；保留逐页身份。
2. 有可靠文字层的页优先原生提取，检测字符异常、重复页眉、双栏/文字重叠等风险；有少量页眉文字的整页扫描图不能误判为正常文字页。
3. 图片/扫描/疑似缺失区域优先本地 OCR；旋转、双栏、低清晰度输出页级警告与原图对照，不用模型补写模糊字。
4. 原生文字与 OCR 块按位置去重合并；同一文字不能既以文字层又以 OCR 重复导入。纯装饰图与空白页须有明确分类依据，疑似正文图不得自动跳过。
5. 本地 OCR 不足且用户同意时，仅将有问题的页/区域交给可用视觉模型；标明实际模型、页数、预算、文字可能有误。视觉描述不能当作原文转录。
6. 封面页只产生候选，用户确认才更新封面；正文插图按资源保留，不擅自变成封面。
7. 展示「总 N 页；原生 A 页；OCR B 页；待核 C 页；失败 D 页；确认空白/排除 E 页」。计数分类必须互斥且总和一致，混合页的区域统计另列。
8. 整体解析超限/失败时保留现有书与已完成解析产物，提示拆分文件或处理指定问题页。严禁只取前若干页后标记整本成功。

## 6. AI 路由、Token 与额度控制

### 6.1 模型选择必须显式

- UI 创建导入任务时传递输入框当前选择的模型引用；服务端验证归属、启用状态与能力。用户没选自定义模型时，本功能固定使用 `basic`，不沿用主 Agent 的高价内置档位。
- 当前选择自定义模型时固定该 `customModelId`，不能使用“最近更新的另一个自定义模型”，失败也不能偷偷切回平台付费模型。
- 基础模型使用 `low`；自定义模型支持 `low` 时使用 `low`，不支持时在预览中展示其实际支持档位并由用户选择后继续，禁止传不支持的参数或静默切到 high/max。
- Job 保存模型配置 ID/版本和实际路由摘要，不保存明文密钥。模型删除/禁用、配置变化或计费路线变化需要重新确认，不把已过期配置继续执行。
- 自定义模型无视觉能力时，仍可用本地 OCR；若需模型视觉补识别，允许用户另选自己的视觉模型，或明确同意平台视觉服务及费用。未获同意就停在待处理页，不能自动旁路。
- 平台模型复用现有 Credits 预留、结算与调用日志；自定义模型按现有 BYOK 规则处理，说明供应商仍可能收费。不得新设一套与现有账务冲突的扣费规则。

### 6.2 只把必要内容交给模型

- 规则可确定的文件全程不请求 AI，不消耗模型额度；本地计算也要受上传/任务配额限制。
- AI 默认只输出结构候选：标题、层级、来源 `blockId`、边界和依据。书名/简介/标签从明确来源提取，不做发布建议式创作。
- 先传目录、标题候选和章节首尾短片段；歧义块才追加。正文整本不进入主 Agent 对话，也不让模型把全文重新输出一遍。
- 拟定初始预算：单次结构请求输入最多 8k Token、输出最多 2k，整任务结构分析最多 40k 输入/8k 输出；还须取模型真实上下文、平台可用额度与用户预算的更小值。这是待压测的默认上限，不是当前能力或费用承诺。
- 超出预算暂停等待用户提高预算或手动调整，不能截去未解析正文。Vision 按供应商图像计量单列预算，先展示页数与上限；没有可靠报价则显示“费用未知”，不显示 ¥0。
- 解析/OCR/结构缓存键包含用户、文件 SHA256、解析器/语言包版本、选项及模型配置指纹；仅本人复用，不跨用户暴露文本。原文块不重复进入上下文。
- 网络瞬态错误最多自动重试 2 次（退避），鉴权/模型不支持/额度不足不自动重试；已返回结果与用量持久保存。供应商超时后用量未知需待核，不把重试宣传成无额外供应商费用。
- 已经提交的任务重放只返回原回执，不再扣费/生成章节；取消停止新调用，已经发生的合法调用按实际账务结算。

## 7. 文件、任务与接口契约（拟新增）

### 7.1 数据实体

| 实体 | 核心字段/约束 |
| --- | --- |
| `NovelImportJob` | userId、novelId、可选 sessionId/taskRootId、状态、来源文件 ID/哈希、解析器版本、模型引用、费用授权、预算、leaseOwner/leaseEpoch、取消标记、错误码、到期时间 |
| `NovelImportSource` | Job 归属、原文件名、内部对象路径、真实 MIME、字节数、SHA256；ZIP 成员清单、页状态、块产物索引；正文不放日志 |
| `NovelImportManifest` | Job + revision 唯一，结构及块引用、元数据选择、排除清单、manifestHash、完整性结果；服务端验证后方可批准 |
| `NovelImportApproval` | 用户真实身份、Job、目标作品、来源 hash、manifestHash、目标 baselineHash、覆盖两步状态、费用同意、expiresAt、consumedAt；审批不可被模型自行构造 |
| `NovelImportCommit` | Job 唯一提交记录、幂等键、提交前/后结构 hash、备份 ID、新旧章映射、计数、回执；与章节写入同事务 |
| `NovelImportBackup` | 原卷章/元数据/相关版本快照及必要资源引用、校验和、恢复期限、恢复状态；支持进程重启后恢复 |

解析大对象放受控持久文件存储，数据库存索引与校验和；不能把整本小说塞进 Runtime 回执（现有 `runtimeJson` 有 2MB 限制）。不使用导出的 15 分钟内存仓库承载导入任务或备份。

### 7.2 状态机

`uploading → validating → parsing → needs_review / ready → awaiting_confirmation → committing → succeeded`

旁路：`awaiting_budget`、`failed`、`cancelled`、`expired`。恢复操作单独记录 `restoring → restored / restore_conflict`，不删除原成功回执。

- 每次状态迁移校验 jobVersion 与 worker leaseEpoch；进程重启由租约机制接管，旧 worker 不可再提交。
- 解析可断点重试；waiting 状态不占着 HTTP 长连接或数据库事务，也不触发 Agent 连续空转。
- 原子提交一旦成功，即使 HTTP 断开也查询到 succeeded；不能因超时再创建第二份章节。
- 提交前取消可确保零作品写入；提交与取消竞争按数据库提交顺序裁决。若提交先完成，提示已完成并提供恢复，不虚报“已取消”。

### 7.3 拟定 API

统一在 `/api/novels/:novelId/imports` 下：

- `POST /preflight`：验权，返回卷章/正文数量、基线、待审/运行任务/发布影响及覆盖入场挑战。
- `POST /intents/:intentId/confirm`：记录第一/第二步真实用户确认；不得一次请求同时确认两步。
- `POST /`：建立 Job；小文件 multipart 流式上传，大文件分片上传经校验合并；不扩大整站 Base64 JSON 请求上限。
- `POST /:jobId/analyze`：确认解析选项及可能的模型费用后开始后台解析。
- `GET /:jobId`、`GET /:jobId/preview`：取状态/分页目录/章节块；SSE 仅作进度增强，断线可回查。
- `PATCH /:jobId/manifest`：带 expectedManifestRevision 保存纠错和元数据选择。
- `POST /:jobId/confirm`：确认具体预览，签发绑定来源、目标基线与预算的提交授权；入场批准过期/目标变化时返回需要重走两次覆盖确认。
- `POST /:jobId/commit`：提交幂等键+批准 ID；后端重验权限/哈希/版本/覆盖两步/高危审批，拒绝 `confirmed: true` 布尔值替代授权。
- `POST /:jobId/cancel`、`POST /:jobId/retry`：幂等取消/从已确认安全阶段重试。
- `POST /:jobId/restore-preview`、`POST /:jobId/restore`：恢复影响预览及独立高危确认。

所有接口先认证再校验资源归属；source、job、manifest、approval、novel 必须同用户同作品，Agent 入口另验任务会话绑定。错误响应使用稳定错误码和用户可执行的恢复动作，禁止泄露磁盘路径/密钥/全文。

## 8. 提交、覆盖、备份与并发安全

### 8.1 覆盖采用保留旧记录的归档方案

不直接 `deleteMany` 清空整本书。章节存在评论、任务、记忆和阅读引用，单纯备份正文后删行仍会破坏关联。

拟对卷/章增加导入归档标记（如 `archivedByImportId/archivedAt`）：旧记录退出**当前创作目录**但保留原 ID、正文、版本与关联；新记录使用新 ID，禁止按章序冒充旧章节身份。旧章深链显示归档/恢复说明，不跳转到同序号的新章。

- 当前目录的唯一约束改为仅约束未归档卷/章的 PostgreSQL 部分唯一索引；实施时核对 Prisma 对部分索引的支持方式，必要时用显式 SQL migration，并增加重复顺序回归测试。
- 全部创作区/Agent/编辑/检索/导出/字数统计入口统一使用 active scope；不能只改左栏过滤。历史审计和恢复接口可显式读归档记录。
- 已发布内容与当前创作稿分离：归档保留 `published*` 快照及公开阅读顺序/卷标题，导入不能让旧读者内容突然消失，也不能把新稿自动公开。需要补齐公开目录/发布更新对替换版本的处理，不可仅给写作查询加过滤就上线。
- **发布兼容是覆盖模式发布闸门。** 如现有公开查询无法独立读取旧发布快照，实施阶段先完成发布目录快照适配；适配未验收前，对已有已发布章节的覆盖必须明确阻止并说明原因，不自动下架。此阻止是灰度保护，不算该场景已交付。
- 可选元数据更新可能影响已有公开作品，预览必须标明影响；未勾选不改公开名称/封面等。发布状态、作品 slug、作者归属不由导入文件决定。

### 8.2 原子提交算法

1. 解析/OCR/AI/图片转码全部在事务外完成，结果落稳定存储并校验；备份和依赖资源可读取才允许继续。
2. 短事务锁定作品写入闸门，复核身份、Job 租约、取消标记、审批、manifestHash、来源哈希及基线。
3. 基线包括活跃卷/章 ID、顺序、revision、正文 hash、待更新元数据；任一新增/删除/改写/移动都会失效。只比章节数量不够。
4. 同事务持久化可恢复快照、归档旧卷章、批量插入新卷章、按选择更新元数据、重算创作统计、消费授权、记录唯一提交回执与 outbox。
5. 验证全书 `orderIndex`、卷内 `orderInVolume`、卷 `orderIndex` 连续且唯一；所有新章属当前作品和用户，字数使用现有统一口径。
6. 提交后通过 outbox 刷新索引/缓存和 UI 订阅，失败可重试；任何事务中异常完整回滚，旧书仍为活跃版本。提交前不产生半本作品。

一批上限范围内先采用短事务批量写入；压测超过事务预算时降低接收上限并清楚提示。不可为追求支持大书改成边解析边删除、逐章部分提交。

### 8.3 与编辑器、Agent、待审的协调

- 解析阶段不锁作品；最终确认后短时锁写入。所有章节/卷/元数据写入入口须遵守同一闸门，包括手工保存、自动保存、Agent 和后台结构任务。
- 同作品有写入中的任务时列出任务名，默认等待/暂停后再提交；暂停操作也由用户明确选择，不静默打断其他任务。只读任务不必一律中断，但提交后上下文标记过期。
- Agent 发起导入时，对发起者仅允许本次导入提交能力，不给它通用写入豁免；其他写入者等待或返回可恢复冲突。
- 老任务恢复时必须重新读取结构和章版本，旧待审补丁标记「源章节已归档，需重新核对」，不能套用到新章节。
- 原章节自动记忆、连续性报告、桥接、索引与 Style DNA 引用按源版本失效；人工记忆不直接删除，关联旧来源的内容标记待复核并从自动有效事实中排除。
- 导入完成不为每章自动触发付费记忆提取/评论/文风学习。只做必要索引维护；如用户选择「学习导入作品」，须单独展示范围与预算并走已有学习机制。

### 8.4 恢复与保留策略

- 拟定导入前版本至少保留 30 天，界面展示实际恢复截止时间；已公开章节和仍被引用的历史数据不得按普通临时文件 TTL 清理。
- 恢复前显示哪些新章/元数据会回退，核对提交后的版本。导入后有新编辑时不覆盖它们：返回恢复冲突，可先导出当前稿或建立新快照后重新批准恢复。
- 恢复是一次新的受审计事务，恢复旧活跃目录并归档导入版本；保留两边记录和事件，不删除成功提交历史。
- 未提交原始文件/解析预览默认保留 7 天；任务运行、待结算、被备份/正文引用的资源禁止清理。用户手动删除源文件需说明是否影响后续来源对照；已导入正文独立持久存储，不随临时文件删除。
- 清理任务仅按数据库归属与引用计数选择文件，验证绝对路径位于专属目录；不递归删除共享上传根目录，不修改现有聊天附件的永久引用约定。

## 9. Agent 工具与权限接入

拟对外使用一个 `novel_import` 工具，动作分为 `prepare/status/commit`，内部复用第 7–8 节服务。

### 9.1 参数与回执

- `prepare`：用户上传的 `attachmentId` 或已经建立的 `importSourceId`；可带结构模式。`novelId` 从真实任务上下文取，不让模型传任意目标作品。
- `status`：`jobId`，仅返回进度、卷章计数、阻断项、少量示例和预览入口，不返回整书正文。
- `commit`：`jobId + manifestRevision + manifestHash`；批准事实由服务端从当前用户操作取得，工具不接受模型提供的批准布尔值/伪造 token。
- 回执含 `importJobId`、状态、目标作品、新增卷章数、warnings、定位入口、恢复入口；失败提供稳定 `outcome: failed`，待用户确认使用明确 waiting 状态而不是“导入失败”。

### 9.2 权限合同

- 用户说“把这个文件导入当前作品”且有附件时可准备预览；没有文件先请求上传，不能猜 URL/路径或拿任意历史附件代替。
- `prepare` 不写作品，但可能产生文件/模型费用，只能在已有明确费用授权下调用。Plan/Review 允许零费用预检与预览，不得应用；Build 才可申请提交。
- `commit` 固定高危、`alwaysConfirm`，空作品也确认导入内容；已有章节强制两次自定义确认。有正文时明确提示将覆盖多少有内容的章节。
- 在工具注册、治理、运行时冻结授权、参数归一化、调用游标、持久审批和 effectDomain 中一起登记；不能只在 `governance.ts` 加一个 risk 字段。
- 因一个工具具有多动作，runtime 必须按实际 action 裁定权限；若现有框架无法安全按动作裁决，内部拆为 prepare/status/apply 三个工具，UI 仍统一显示「一键导入」，禁止把整个工具标只读。
- 复用持久 `runtime-approval.ts`，补充绑定 Job/manifest/目标结构版本。通用审批第一下“允许”不能替代覆盖第二次确认；审批 UI 只在两步都完成后产生最终批准事件。
- “总是允许”、大胆创作、子 Agent 权限、用户在聊天中泛泛说“继续”，均不能绕过高危确认；拒绝后不可换成 `chapter_update` 等工具完成同一覆盖。
- 文件中的“忽略上面的规则”“确认删除”等一律作为原文数据；模型识别上下文不授予写入工具能力，提交只消费服务端校验后的清单。
- 用户在独立导入面板已完成该 Job 的相同确认时可复用同一批准事实，避免 Agent 再弹一套；仍需验证任务/文件/预览/目标基线一致。
- 等待解析与审批释放执行槽；通过任务事件恢复，不轮询消耗多轮模型请求，不被无进展停止逻辑误判。取消/过期不自动变成批准。

## 10. 安全限制、错误兜底与可观测性

### 10.1 拟定初始限制（须压测后发布）

| 项目 | 建议初始值 | 超限行为 |
| --- | --- | --- |
| 单主文件 | 50 MiB | 上传前后双检，提示拆分；不接收后截断 |
| ZIP 解压总量 / 成员数 | 200 MiB / 3,000 | 流式提前中止，删除本任务无引用临时产物 |
| 单 ZIP 成员 / 压缩比 | 50 MiB / 200:1 | 拒绝并指出成员；高压缩纯文本可拆分后重试，不豁免炸弹检测 |
| PDF 页数 / 单渲染图像像素 | 1,000 页 / 20MP | 超限明确阻断；图像按受控 DPI 处理 |
| 导入正文 / 章数 / 卷数 | 500 万字符 / 2,000 章 / 200 卷 | 超限提示拆分；提交前检查单章契约上限，不截断超长章 |
| 单用户活动 Job | 1 个执行、2 个排队 | 超出提示排队/取消旧任务；不同作品并发受统一配额控制 |
| Worker 起始资源预算 | 单任务 1 CPU、1GiB；单文件原生转换 120s、单页 OCR 60s；整任务执行 30min | 超时保留检查点并报告；不是吞错成功，不占 API 主进程 |

全站 worker 并发由部署机器预算决定，初始 1；上线压测达不到上限要降低对外限制或扩容，不承诺小型服务器同时处理多本千页扫描书。恶意压缩检查也覆盖 DOCX 内部容器。

### 10.2 主要错误与行为

| 错误码（拟） | 用户提示/处理 |
| --- | --- |
| `IMPORT_UNSUPPORTED_FORMAT / FILE_TYPE_MISMATCH` | 展示允许格式或真实格式不匹配，重新选择 |
| `IMPORT_ARCHIVE_UNSAFE / IMPORT_LIMIT_EXCEEDED` | 展示安全原因/超限项目，不继续处理整包 |
| `IMPORT_PASSWORD_REQUIRED / IMPORT_CONVERT_FAILED` | 请先移除文件密码或另存格式；不反复调用 AI |
| `IMPORT_ENCODING_AMBIGUOUS` | 展示编码样例供选择，保留原字节 |
| `IMPORT_NO_BODY / IMPORT_INCOMPLETE_CONTENT` | 显示未识别正文/问题页，修复或显式排除；不空覆盖 |
| `IMPORT_MODEL_UNAVAILABLE / IMPORT_VISION_REQUIRED` | 选择合适模型或本地 OCR，不暗中切换计费模型 |
| `IMPORT_BUDGET_REQUIRED` | 显示已发生用量及剩余问题范围，确认新预算或人工完成 |
| `IMPORT_TARGET_CHANGED / IMPORT_WRITE_BUSY` | 旧书未改动，刷新对比/等待任务结束并重新确认 |
| `IMPORT_APPROVAL_REQUIRED / IMPORT_APPROVAL_EXPIRED` | 回到自定义确认，旧批准不可重放 |
| `IMPORT_COMMIT_FAILED / IMPORT_RESTORE_CONFLICT` | 保留原书/两版本，给出重试或安全恢复入口 |

### 10.3 日志与管理员统计

- 记录 userId/novelId/jobId、格式、大小、解析器版本、各阶段耗时、总页数/问题页数、章数、失败码、调用次数、Token 与账务状态、批准事件 ID、提交/恢复回执。
- 不记全文、原始 API Key、私有下载 URL；错误报告脱敏。日志可按 jobId 串联上传、解析、审批、账务和提交。
- 创作记录中新增导入统计：准备成功率、提交成功率、部分导入率、扫描页待复核率、格式/解析器失败排行、取消/拒绝数量；取消不计为工具崩溃，部分成功不计为完整成功。
- 指标分母分别定义：解析成功/解析终态任务；提交成功/已授权提交尝试（重放去重）；不能用同一百分比混合处理所有阶段。

## 12. 验收矩阵与发布闸门

本轮不运行功能测试；下列是实施后的验收合同，不是已经通过的报告。用户线上验收不能替代破坏性写入的隔离数据库安全回归；不在生产拿用户章节做覆盖试验。

| 场景 | 必须验证的结果 |
| --- | --- |
| UTF-8 / BOM / UTF-16 / GB18030 TXT | 中文无乱码、章序正确；歧义编码可选；规范化之外正文与金标准逐字比较 |
| MD 标题、代码块、引用、目录 | 不误切正文中的标题文字，不重复导入目录；段落与场次保留 |
| 本站全量/部分导出 ZIP | 对选定正文的卷/章/顺序/内容往返一致；全量目录不会造成部分导出包补出不存在章节 |
| 普通 ZIP / 多书根 / 重名章 | 自然排序、显式选一本；不同章同名不互相覆盖；失败成员可见 |
| ZIP Slip / 炸弹 / 链接 / DOCX 炸弹 | 受控失败、零越界文件写入、资源限制生效 |
| 真 DOC / DOCX 标题/表格/图片/修订 | 非伪装 DOC 测试；不遗漏剧本表格对白；不执行宏或网络请求；未处理对象有提示 |
| 文本 / 扫描 / 混合 / 旋转 / 双栏 PDF | 每页有状态，原生/OCR 不重复，页数计数守恒；问题区域可查看，不静默漏页 |
| OCR 金标准集 | 干净印刷体样本设置字符错误率 ≤2% 的初始质量门槛，低质量样本不保证达标但必须进入待复核；阈值需实测校准，不发布未经测量的成功率 |
| 图片/扫描正文全部失败 | 不能显示整本成功或空覆盖；已有作品 hash 完全不变 |
| 空作品 / 已有空章 / 已有正文 | 空作品预览确认；其余两次独立覆盖确认；第二次取消零作品写入 |
| 预览改动 / 路由 A→B / 新增旧章 | 批准失效、返回冲突；绝不写错作品、不自动重建任务 |
| 刷新 / 断网 / 双击 / Worker 重启 | Job 可回查；最多一次提交；旧 worker 被 fencing 拒绝；未知结果不盲重试 |
| 事务中故障 / 磁盘满 / 备份不可读 | 旧书活跃目录完整、无半写入；备份失败不得执行覆盖 |
| 编辑器/Agent 并发 / 旧待审批准 | 同一写入闸门与版本校验有效；旧补丁不落到新章节 |
| 已发布作品 / 评论 / 阅读进度 | 导入不发布、不改变已有公开正文和原章身份；发布新版本需独立确认；旧链接/评论不挂到新内容 |
| 恢复 / 恢复前已有新编辑 | 可恢复旧卷章/元数据；新编辑冲突不丢失；保留完整回执 |
| 自定义模型两份以上 | 使用本次指定模型而非最近更新模型；不支持 low/vision 时提示，不静默换付费路由 |
| 额度不足 / OCR 超预算 / 用量未知 | 暂停、预留和结算正确；确定性导入仍可使用；不可记未知为 0 |
| Agent 拒绝/超时/子 Agent 尝试提交 | 必须阻止；不得凭自然语言或通用 alwaysAllow 代替批准 |
| Windows / Android / 手机网页 | 文件选择、拖放增强、返回、键盘、安全区、预览持久化与按钮防误触分别实测 |

固定夹具以自有/授权文本为主，每个样本附预期书名、卷章结构、段落/字符数、页/成员覆盖清单及输出 hash。PDF/OCR 的内容正确率与结构识别率分别统计；随机人工抽查首/中/尾章不能替代全块覆盖检查。

实施后的四闸按仓库工程规范执行：类型检查、lint、单元/集成测试、构建；持久审批/事务/并发测试使用隔离数据库。随后同一提交 CI 成功、受控灰度及三端人工验收。需要重启后端或暂停线上任务时，按当次授权操作，不把历史授权自动延伸到本方案。

## 13. 分阶段执行与完成定义

### P0：安全与兼容探针

锁定六种格式样本、MarkItDown/转换器/OCR 候选版本；核对全部活跃章节查询、公开阅读/发布、记忆引用、待审与备份恢复行为；测容量并冻结契约。产出依赖许可证清单、解析质量报告、发布兼容迁移设计。

**出口：** 归档/恢复与公开快照方案能通过隔离数据库验证；DOC/OCR 真实样本可处理。不能直接跳到 UI 开发然后再决定如何保护旧书。

### P1：确定性导入完整链路

完成持久上传/Job、TXT/MD/DOCX/本站 ZIP、卷章预览、两次确认、版本绑定、原子提交、恢复与 active scope。导入开关默认关闭；扫描 PDF/DOC 未交付不能在界面伪装支持。

**出口：** 无 AI 的样本零模型调用，原文/结构往返验收，故障注入无内容丢失。

### P2：DOC、PDF/OCR 与局部 AI

部署隔离 worker、逐页覆盖、图像资源、疑难结构分析、本次模型路由、预算/用量/取消/缓存；上线前完成全部六格式验收及已发布作品兼容。

**出口：** 所有未处理内容可解释，费用经授权，不能出现“实际只有部分内容，界面显示完整成功”。

### P3：Agent 与三端交付

接工具权限、持久审批、waiting 状态与导航回执，补齐手机全屏流程、Windows/Android 文件选择和取消恢复；管理员记录可定位失败。

**出口：** Agent 与手动入口使用同一服务、同一确认与版本约束，危险覆盖无法从其他模式绕过。

### P4：灰度、发布与恢复演练

先管理员与白名单用户灰度，区分手动导入、Agent 提交、OCR、已发布作品覆盖的开关；解析 worker 独立健康检查。观察失败码/耗时/内存/费用与完整性报警，再扩大范围。

遇到数据一致性/越权/未授权覆盖立即关闭提交能力，保留状态查看、报告与恢复；不能通过回滚旧服务而丢掉归档过滤。包含数据迁移后的代码回滚须兼容新索引/归档字段，必要时前向修复，不破坏备份。

**最终完成：** 用户从作品菜单或 Agent 附件进入，六种格式均有可验证处理路径，能预览/修正/确认/导入/恢复；扫描和不完整文档不误报，模型选择与费用透明，旧稿与公开内容受保护，手机与桌面均验收通过。实现记录需列明真实通过/未测/受限项目，不以本方案或 CI 通过代替生产验收。
