# 内容治理与测试通道

管理后台的「内容治理」提供举报及投诉、Agent 安全记录、异常使用与对账、处罚、申诉。打开案件详情会留下调阅记录。管理员应在有实际需要时查看目标材料，对举报人和被举报人分别说明处理结果。

## 举报与复核

从具体对象的更多操作进入「举报与投诉」，私信在所选消息上取证。公众入口为 `/report`。保存提交回执以便查看进度、补交材料。独立申诉入口为 `/appeal`。使用本人身份核验后查看案件或纠正提醒。受限核验凭据仅用于申诉。核验完成后确认实际处理范围、期限和依据，提交说明，并在同一入口查看结论。

先确认受理，再从收到必要材料起计算反馈期限。工作日口径为中国标准时间，运营者按官方工作日历维护 `GOVERNANCE_HOLIDAYS` 与 `GOVERNANCE_WORKDAYS` 的日期例外。紧急情况优先核查。延期时向提交人告知原因和预计完成时间。举报重复时关联同一事项，保留各自回执；核查证据不足时选择「不成立」。公开内容可走原有下架/恢复流程，账号处分另行确认。

## 处罚与纠错

核对用户和已确认事实，按行为选择作品与章节评论、帖子评论、发帖、私信、发布作品或创作 Agent。全平台限制须单独确认。填写具体理由、条款、截止时间。撤销或调整时记录复核结论，并逐项核对其他仍有效的限制。对疑似账号被冒用者优先协助恢复。

Agent 风险信号先进入待复核。普通拒绝、服务故障、自动重试和正常修改创作主题都不足以认定违规。按原始用户动作去重，并确认有持续规避的证据后才进入升级判断。测试配置为滚动 30 天，一级限制 7 天，默认观察。观察结果供复核。人工纠错后核对有效事件数、已关联措施及本人通知。

## 使用异常与三方对账

云枢使用后台现有固定来源及只读配置。对账页可按本地业务或用户查询。平台文本调用从指定云枢响应取得网关签发的请求编号，与上游日志逐项查找；普通用量按 `usage:` 扣款键、持久 Agent 按 `operation:` 扣款键追溯，使用原 V1/V2 费率、缓存和原优惠信息复算。上游 quota 与 Credits 单位不同。对无法证明同源的历史调用、未覆盖的业务、非独占令牌、缺少计量、预约、费用优惠、供应商退款与本地退款，保留原始证据和待核实状态。固定费用独立展示图片和联网工具的账本回执，按原始业务快照核对。若有目标用量记录，则显示当时归集的微 Credits 和预留 tokens。对账差异先由账务维护者核查，不能据此判定用户故意违规。

## 事务邮件

处罚、提醒和申诉复核的通知意向与状态变化同事务写入。队列按事件、类别、接收人去重，使用经验证的邮箱。治理通知与运营活动的发送权限和模板独立。管理页区分模拟、待发送、已接受、送达、退信、抑制及结果待核。未知结果保留原记录。系统重启后不自动重发。抑制或发送失败时，应从本人申诉与允许的联系渠道告知。

`GOVERNANCE_MAIL_MODE` 默认关闭，关闭期间产生的历史记录不补发。隔离测试用 `mock`。真实白名单方式为 `tencent-allowlist`，须由获授权的维护者在可用的申诉入口、香港地域发件人、回信邮箱、模板审核及具体接收地址均核验后设置。发件人为 notice@chevolink.com。独立配置项为 `GOVERNANCE_SES_SECRET_ID`、`GOVERNANCE_SES_SECRET_KEY`、`GOVERNANCE_SES_REPLY_TO`、`GOVERNANCE_SES_ALLOWLIST`、`GOVERNANCE_SES_WARNING_TEMPLATE_ID` 及 `GOVERNANCE_SES_ENFORCEMENT_TEMPLATE_ID`。运行期核对审核状态及原件，申诉结果模板仅供预览。审批、配置 DNS/CAM、试发、解除抑制均属于独立运营操作。

## 数据迁移和撤回

向前迁移增加治理案件、处罚与安全记录、事务邮件记录、网关关联表和索引。迁入旧全封记录时保留原账号的封禁和会话语义。上线前应核对相同提交的独立 PostgreSQL 门禁、前端不可变产物、实际 API 和当前生产版本。测试产物须携带 `platformGovernance` 及基线已有能力。测试分流共用 API，已接受任务的模型、计价及已保存内容继续以各自原业务记录为准。

如需撤回，先按版本管理预览撤回测试分流，并按原操作号确认结果；需要时关闭自动处分及事务投递。保留案件、已生效的独立限制、审计、发信 attempt 及有效申诉通道。已经实施的错误处分须在后台逐项撤销和纠错。涉及服务端回退时先核实旧版对现存受限账号的执法能力，确定兼容版本和权限恢复方案；不得通过删除表或重放部署恢复。
