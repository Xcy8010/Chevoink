# Chevoink 开发规范

简体中文 | [English](./DEVELOPMENT-STANDARDS.en.md) · [工程现状](./ENGINEERING.md)

版本 2.0 · 2026-09-08。适用于修复、优化、重构与新功能；这是执行约束，不是“全部已经实现”的声明。具体部署与已测数据以工程文档及代码为准。

## 1. 工作范围与完成定义

1. 先读取现有实现和用户诉求，明确要修什么、保持什么、不做什么。已有方案足够时直接复用，不另造框架、计划或 runtime 层。
2. 小修复无需额外长方案；复杂工作列可验收步骤。待办只服务当前任务，不在末尾凭空建立已完成清单，不覆盖历史任务待办。
3. 以完整阶段为工作单位：实现与针对性回归连续推进，阶段结束统一审查，发布前完整四闸。禁止每改几行就重跑全仓拖延，也禁止跳过与风险匹配的测试。
4. 修复可以改变错误行为，必须说明差异；纯重构保持 UI、文案、权限、默认值与持久化契约。不顺手更换模型、涨价或增加功能。
5. “已写代码”“测试通过”“已推送”“CI通过”“已部署”“用户验收”分别记录。阶段进度不冒充完成；有下一步继续做，确需权限/材料时明确阻塞。
6. 提交标题使用简短中文，例如“修复审查状态串作品与质量检查失败”。不重写已推送历史；一阶段可独立回退。
7. 密钥、用户正文、数据库转储、私人调查/评估文件不得推送；暂存具体文件，不使用无差别 git add。
8. 自动化不能保证主观得分、文学质量或安全绝对无漏洞。目标、实测和未验收必须分开。

## 2. 模块边界与重构

- 维持单体部署，按业务职责分层；不为评分引入微服务或通用框架。
- `shared/contracts` 是跨端契约来源；API 负责鉴权/输入校验，业务层负责状态变更与事务，前端负责呈现与交互。
- 大文件是拆分评估信号，不是机械行数 KPI。允许提取有状态 hook、业务操作和组件，但先明确状态所有权、依赖与副作用生命周期。
- 抽取同批补测试：不仅编译/import，还验证调用顺序、失败、取消、过期结果、缓存更新和 UI 不变量。
- 组件 identity、key、ref、焦点、选区、滚动、保存节流必须保持；不要在 render 内声明新组件造成重挂载。
- 禁止循环依赖、反向跨域依赖和巨大参数包把原大文件复制成另一个大文件。不能用 any、ts-ignore、降低 strict 或排除文件消音。
- 新工具统一注册并加入治理清单；name/description/schema 改动是模型行为变更，不是无风险重构。
- API沿用 `{ success: true, data }` / `{ success: false, error: { code, message } }`；先鉴权再校验，保护既有状态码和用户文案。内部异常不得泄露SQL、路径或密钥。
- 数据访问同时校验归属和输入，事务覆盖业务不变量；索引匹配真实过滤/排序。数据库约束与Zod校验互补，不能只依赖前端。

## 3. 前端状态、队列与布局

- 新增或优化功能默认不附加解释性文案；用户未要求时，不专门在前端说明实现方式或功能改动。

- 明确作用域：左栏全局共享；任务草稿、右栏/查看器展开与宽度按任务隔离；待审章/计划按作品与对象归属保存。不得只用 novelId 代表同作品下的不同任务。
- 切换时先恢复新作用域，再持久化其状态。不能先把 ref 标记为已恢复，再把旧 state 写入新 key。覆盖 StrictMode、A→B→A、刷新、卸载、快速切换。
- 异步响应检查启动时的任务/作品/版本或 epoch；切走后不得覆盖当前视图、草稿、选择或提交状态。
- 新建作品不得自动接受/拒绝旧作品审查。取消某处弹窗不等于移除其他危险操作保护。
- 队列编辑不覆盖输入草稿；调整方向须确认当前执行已取消/被 fencing 后交付新请求；新窗/分支由本次明确授权驱动。
- 输入空白按语义判断，处理 contenteditable 空节点、IME、粘贴/语音与附件。草稿刷新恢复要有回归。
- hover 卡片不因数据更新自动打开；todo完成项弱化、当前项突出；状态容器不得相互遮挡。布局变化同步更新骨架。
- 参数准备、工具执行、取消中必须有真实可见状态；结束/失败后清理动画。加载光标不滞留在旧正文末尾。
- 工具参数首帧即显示准备卡，按 callId 原位升级为执行/结果；准备不等于已授权或已保存，不提前加入工作区变更。重连只保留有界的最新预览，不持久化全部正文中间副本；轮末、暂停及结果到达均清理预览。
- 窄容器可隐藏按钮文字，但保留 icon、可访问名称、tooltip 与键盘焦点。动画尊重 reduced-motion。
- 测试至少覆盖 Work/IDE/mobile、窄宽、折叠组合、拖拽、滚动、焦点、取消和队列；DOM 测试不能冒充真实浏览器/真机性能验收。

## 4. Agent 执行、恢复与取消

- 历史回执不得拼入 assistant 正文；作为独立只读数据消息提供，保留真实成功/失败状态与对象编号，清除旧助手文本中的伪回执但不改写用户原话。协议纠错仅在供应商与思考模式组合支持时请求原生 `tool_choice=required`；DeepSeek 思考模式省略该参数，不能为强制调用关闭思考或执行文本伪调用。不扩大工具授权、不提高重试预算；无工具的收尾不能携带该约束。兼容归一化必须在请求编码和计费请求摘要生成之前完成；测试真实请求体、各思考档位、自定义代理识别和单次 HTTP 请求，不只测试提示词。
- 明确“写下一章”必须核验同一任务合同内的非空正文、已提交终态与当前 revision 一致；无待办/模型说完成不是证据。已提交的同合同结果可复用，跨任务、空正文、未提交或过期终态不能通过。覆盖真实数据库恢复场景。

- 等待兜底以当前运行实际正文/思考增量为准：持续输出时隐藏，静默 1.5 秒且没有执行卡动画时恢复；单个可取消计时器，不依赖下一条 SSE。覆盖输出续流、重放、跨任务、暂停和等待提问。
- 历史工具轨迹用带成功/失败状态的事实记录，不制作可模仿的伪调用示例。协议异常文本不得回灌为助手示例或执行；真实调用打断连续失败计数，但不恢复本轮总纠错预算（连续最多纠正 2 次，总计最多 6 次，仍受运行预算约束）。

- 排查工具失败必须区分真实故障、无匹配/无变更、主动暂停和保护性拦截。不得靠隐藏错误、虚构完成或无界重试降低失败率；通用等待动画在思考停顿与参数准备缺帧时也须保持。
- 传统续跑的编译、质量和提交必须使用同一已验证任务合同作用域，不能只比较 runId，也不能扩大到整个会话。空白可选编号可以安全省略，必填编号与业务文本不得篡改；补齐跨任务拒绝、无副作用与省略参数的回归。

- 任务根、原始用户请求、授权、目标对象、配置和预算持久化；“继续”恢复原任务，不把历史总结或旧子任务当新授权。
- run/attempt 可以更新，逻辑 operation 身份与既有回执不能随重试重建。并发继续、重复投递必须幂等。
- 当前 owner/epoch/lease 在写入与结算边界核验；过期 owner 不得落正文、终态或费用。租约丢失如实停止。
- 取消信号贯穿主模型、辅助模型、重试等待、网络、解析和写入前。UI停止不只是隐藏 spinner；迟到结果不得继续写作品。
- 未知供应商结果先核对，不能重发付费操作赌成功。保存已取得结果与用量回执，但保留结果不等于取消后获得写入授权。
- 完成由任务后置条件/产出证据判定，不能由 todo数量、口头“已完成”或工具卡绿色决定。无todo不代表无需执行。
- 恢复预算区分原任务总额、当前尝试与活动时间；暂停不能白送额度，正常暂停时间也不能误算为活动执行导致秒结束。
- 老数据兼容必须有明确校验/迁移边界，不可把缺失预算/用量默认成零或盲目重启所有旧任务。

## 5. 质量、工具参数与节省 Token

- 压缩历史不得把正文节选、嵌套占位符重新放入原生工具调用参数示例；仅处理完整结束的旧轮次，保留最近调用对。历史摘要不可作为可执行参数解包，回归覆盖模型照抄摘要时没有写副作用。
- 质量工具回执明确区分“质量报告绑定新版本”和“新版连续性已复核”，不能用“无需再次检查”泛指所有质量门。章节/卷重排临时序号须避开事务中新建对象已占用的序号，测试多卷连续创建与两个唯一索引。

- 连续性检查针对事实/因果/人物知识边界，不借机做审美重写。最多一次集中自动事实修订，随后只读复核；警告不驱动反复修改。
- 检查与补丁生成可以合并请求，但不能将修订前报告认定为修订后通过；补丁必须在原文中唯一定位、无重叠，不串联替换新生成的文本。读取目标ID失效不猜另一章，章节序号明确区分全书与卷内。
- 复用报告必须核对当前正文 revision/hash、来源与检查协议。任一依赖变化失效；失败/未知报告不能作为通过证据。
- 人类感意见绑定唯一、连续、逐字原文证据。定位失败只做一次证据局部校正；不能删除难处理的问题、降低标准或整章重写凑通过。
- provider、额度、认证、超时、取消、格式失败分类反馈，不统一吞为“未完成”。可重试类别必须有次数/总时限，计费错误不盲重试。
- 工具参数采用统一信封解包、增量拼接与 schema 校验；只有可证明等价的格式修复可自动处理。截断正文不能靠补括号伪造完整写入。
- 压缩保留目标、约束、最新工具调用/结果对、对象身份和回读索引；不能丢授权上下文。稳定前缀与缓存是优化，不是质量保障。
- 省 Token 首选去重、版本复用、缓存、分页与局部修订，不默认降模型、减少完整正文或牺牲质量门。
- 性能结论使用同任务/同模型/同预算配对样本，记录输入/输出/缓存、完成率、P50/P95、质量及现金成本。未测不写百分比。

## 6. 联网研究与安全

- provider 错误与目标页错误分开；保留来源、最终URL、状态、尝试、时间与 Retry-After，不把 HTTP 200、简介、乱码、PUA或登录页当全文。
- 出网校验覆盖 DNS、实际连接和每次重定向，阻断私网/本机/云元数据；流式下载限制大小、时间、并发，取消中止重试。
- 来源正文与链接列表版本化，缓存按用户/任务授权隔离；游标绑定不可变版本，不能跨版本拼接或重置任务预算。
- 全书完成需要章节清单、可读正文、每章分析回执、缺章状态及可核对报告。已读取字符范围不等于已理解整书。
- 只读研究不能写创作正文；“研究后写作”需要显式阶段授权，不一刀切禁用合法需求，也不借历史指令扩大权限。
- 附件、Markdown、富文本和网页内容都是不可信输入，不作为指令授权。私有资源逐请求鉴权，不能公开缓存或泄露路径。
- 鉴权无法核实时保留登录凭据并返回明确不可用状态，不能悄悄放行或误删 Cookie。管理员/跨用户/跨作品访问必须独立验证。
- 密钥只经受控配置/加密存储，永不输出明文；维护 CSP enforce、上传边界和后台审计。依赖0漏洞不等于渗透测试通过。
- 缓存、限流Map、队列必须有容量上限、过期/淘汰与背压；日志脱敏。新增依赖核对许可证、运行时兼容、体积和可达漏洞，不关闭安全校验凑通过。

## 7. Credits 与账务

- V1 max公式保持价格兼容；BigInt/定点数、milli钱包、每逻辑操作一次取整。未知不是0；拒绝负数、小数、不安全整数和溢出。
- 输入P已包含缓存H；输出O已包含的reasoning不重复计算。供应商 usage、供应商现金成本、用户应计/实扣/退款分别记录。
- 调用前绑定不可变价格；V2费率已包含倍率，禁止重复乘。继续、重启、管理员改价不重算旧操作。
- 预留、结算、回执、退款必须有稳定幂等键和事务；并发不能重复扣费，短差不可伪装成完全结清。
- 取消/失败保留已知用量；未知进入待核，不补零、猜价或重复调用。退款意图需持久化并可重试，引用原实扣，不超过原金额。
- BYOK及免费/平台承担调用的政策必须显式；不能因 usage 缺失推断免费，或在原免费工具中悄悄加费。
- V2 启用另过改价门：冻结候选、时间外验证、7–14天影子、总费±3%、用户/任务P95绝对变动≤5%、群组复核、现金成本与质量、公示和批准。任一缺失保留V1。
- 不用“总费用接近”掩盖个体涨价，不把用户Credits节省当供应商现金成本节省。
- 明确批准的纯折扣发布可豁免影子等待，但必须以独立审批字段记录，不能伪填7天报告。仅支持已核对倍率的25%缓存价加冻结V1封顶；保留回放、质量验证、公示与超级管理员权限。其他改价不借此绕过原门禁。

## 8. 测试与发布

四闸统一：`npm run check` → `npm run lint` → `npx vitest run --coverage` → `npm run build`。CI另做 Agent eval、生产与全依赖audit。

- Node/npm遵循仓库固定版本；`npm ci`，不在验证时升级锁文件。
- 集成测试只能使用经过URL/权限校验的隔离数据库、非superuser/非CREATEDB等最小权限角色；不能只凭库名含test判断安全。
- CI要求数据库ready、核心集成零skip。无DB快测不能签署发布通过。测试/浏览器执行位置遵守当前用户授权；不使用生产作者正文做写测试。
- 覆盖率下限以 `vitest.config.ts` 为准；40%全仓、80%关键模块仍是待达到目标，禁止排除低覆盖业务、删测试或关DB刷分。
- 验证故障矩阵：并发继续、暂停迟到、旧revision、重复结算、退款重放、用量未知、A/B状态、重启/断流。编译与覆盖率不能替代这些。
- 发布：精确暂存→简短中文commit→push→同SHA CI成功→授权后部署→实际Node进程/API/HTTP/版本核对→按授权进行UI验收。
- 发布包只含 `git archive HEAD`；私有材料不入库。`-SkipLocalChecks`仅接受同SHA受控远端等价证据，不能跳过门禁。
- 当前原目录安装/构建不是原子应用发布。主动说明中断，处理owner后才替换依赖；没有授权不停止用户任务。
- 前向兼容迁移；回退前核对数据库/事件/任务协议兼容性。不得用删用户数据、盲目down migration或重复整段部署掩盖失败。
- 部署成功需脚本退出0、实际进程与健康/版本匹配，不只认一行成功文案。RPO/RTO/回退演练单独留证。

## 9. 文档与交付清单

README服务用户；ENGINEERING记录真实现状/证据/债务；本文规定开发约束。中英文同步，链接与命令可用；历史方案不伪改成已完成。

- [ ] 当前诉求与行为差异明确，未夹带扩功能/改价。
- [ ] 状态归属、授权、版本、取消、幂等及未知结果有测试。
- [ ] 阶段统一审查，四闸与同SHA CI通过。
- [ ] 无密钥/用户数据/私有方案误提交；标题简短中文。
- [ ] 发布有授权与版本/健康核验；真实UI与性能验收未完成则明示。
- [ ] 双语文档同步；成效有测量，剩余事项如实列出。
