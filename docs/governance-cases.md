# 举报、投诉与申诉

测试版本在帖子、作品、作者主页的操作菜单以及评论菜单提供「举报与投诉」。私信会话的更多菜单仅提交所选一条消息。设置和政策页提供公众入口。平台投诉与产品意见分别处理。

## 接收与复核

外部举报人可以保存回执中的案件编号和查询凭据，在 `/report` 读取进展、补交管理员请求的必要材料。查询凭据仅向提交者展示，请勿转发。已登录举报人另可收到个人通知。主管理员或已有后台管理员可以查看治理案件；打开证据、修改状态和处置会留下审计记录。举报人信息不随被举报账号的处置通知披露。

案件显示两项截止时间。收到提交后 3 个工作日内确认受理，材料齐备后 15 个工作日内反馈结果或进展。首次提交的材料作为初次反馈期限的起点。确有材料不足时使用「请求必要材料」写明缺项；补交后服务端重新计算反馈期限。延期需在原期限前告知原因和新的预计完成时间，紧急事项优先处理。排班按北京时间计算。维护者须依据当年公布的工作日历配置 `GOVERNANCE_HOLIDAYS` 与 `GOVERNANCE_WORKDAYS`（逗号分隔的 YYYY-MM-DD 放假日、调休工作日）；缺省按周一至周五估算。法定特殊时限由处理人员另行核实。

相关举报可关联到同目标的开放主案件。主案件结案时，每名举报人取得自己的最终回执。账号处置与案件结论分别操作，管理员可从案件详情进入目标账号，核对条款、范围和期限。异常使用页面可登记独立证据引用与待查事实；正常高频使用、同 IP、计量差异或单个风险信号不足以据此处罚。疑似盗号先保护与恢复账号。

公众证据仅截取必要片段。私信要求账号为该直聊参与者，私稿不可用作公开作品证据。目标删除后保留既有案件快照。结案默认安排清理证据；确有继续留存依据时，复核人员填写保留期限，并在内部处理依据中记录理由。后台按到期时间批量清理快照与提交说明，保留案件编号、状态、审计与回执。不得把私稿、无关身份资料粘贴进处理理由或进展通知。

## 受限身份和测试分流

`/appeal` 支持绑定账号的密码独立核验，受限凭证在当前页面内存中保留 20 分钟，仅用于查看和申诉本人决定。启用 `GOVERNANCE_APPEAL_EMAIL_ENABLED=true` 后可使用独立用途的绑定邮箱验证码，应先确认真实发送授权。站内普通会话不由该流程创建。历史限制、逐项处置、错误提醒可分别复核。申诉材料和结果可在此查看。处理结果的事务邮件通过治理专用队列。

在共享 API 的测试分流期间，提交公众举报必须通过当前请求的 `platformGovernance` 能力检查。匿名分配仍取稳定版本；稳定版本拥有该能力后才开放匿名举报。受限账号可在已分配测试版或已有治理案件时独立核验；历史迁入封禁本身不触发测试分配。

隔离预览可直接打开 `/appeal/index.html`，该构建入口与应用内 `/appeal` 共用同一套申诉界面。只发布测试产物时，已退出正常会话的公网访问通常仍由稳定版启动；旧稳定版 r91 不包含此路由。正式启用处罚邮件前须在无登录环境对固定地址完成实际验收。测试发布不改变稳定站点公共静态目录或 nginx。
