# 主 Agent 解释正文任务

新创作区在 build 请求携带 `agentWritingProtocol: 1`。服务端仅对真实作者的全新主任务启用；历史继续、目标任务的自动续跑及子任务保持各自原合同。

## 理解与执行

主 Agent 根据完整原请求、编辑器上下文及必要的目录/正文读取，自行识别新写、修改、检查与章节范围。正文操作前调用 `task_scope_bind`，使用真实章节 ID 或全书序号提交目标；普通讨论直接答复，无需章节绑定。没有独立的分类模型请求。

原关键词解释保留作旧协议兼容。新协议不据此删除正文工具、冻结 `needs_input` 或要求作者重说已给出的目标。编辑器 `chapterIds` 是上下文，不替代主 Agent 判断的真实目标。

系统负责可以确定验证的边界：真实作者来源、作品和章节归属、当前运行与租约、只读模式、真实选区、保护章节及正文版本。绑定凭证作为内部 artifact 记录，关联原请求和任务根；同一绑定可复用，换目标或扩大范围会冲突。原请求、任务根与历史哈希保持不变，子任务读取同一有效绑定。

主 Agent 提交 `locality: local` 时，先读当前正文再定位，用唯一原文或明确坐标作精确补丁。系统禁止借局部修改覆盖整章，并校验明确保留文字。实际 UI 选区继续约束选区外原文。`requiredChecks` 默认连续性与人类感检查；仅依完整作者要求填写合法豁免，检查本身不能扩大正文权限。

绑定不是完成证据。准备、编辑、质量与终态读取统一有效投影；完成仍须核对已保存正文、当前版本的必需检查和真实提交。新协议使用当前章节交付证明，不依赖“仅输出标题和正文”的自动展示开关。

模型仍可能理解错误；结构校验不能证明文学语义正确。回归覆盖自然表达和实际工具执行，不能据此宣称所有模型、真实收费调用或设备体验已验收。

## 历史误拦

旧动作绑定器曾把真实作者已选定的单章修订标成 `needs_input`。只在原始作者来源、已接受修订动作、唯一真实章节及无冲突等证据齐全时派生只读纠错，不改写旧合同。

用户主动继续时，仅真实准备失败后、内容确为重复确认同一章节的问题可以解除过时等待标记。未知问题、剧情选择及混合创作选项仍等待真实回答。部署不会自动恢复旧任务或重写已完成章节。
