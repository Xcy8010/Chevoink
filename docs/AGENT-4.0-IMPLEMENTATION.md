# ChevoInk Agent 4.0 产品与实施方案

工程执行版本：1.2　日期：2026年10月22日

状态：P0已取得真实失败与离线重放；P1及P3候选复核兼容链已通过完整测试分片；P2已实现简短任务指引、持久准入权限对齐和首组上下文去重，能力目录收敛仍未完成。P4首组10项工具已实现，集成验证中已修复冻结身份比较与调度夹具问题；其余27项及新任务默认切换、P5–P6未完成。阶段CI曾被依赖审计及新增集成用例阻断，失败记录保留，当前修正仍须新SHA完整CI。本文件是工程内唯一执行计划，不代表部署或产品验收已完成。

## 1 需要达成的结果

4.0 以作者完成创作为目标。主线是：**理解意图 → 读取相关内容 → 写作或修改 → 交付实际成果**。聊天、设定讨论和研究可以独立完成，不必先选章节或生成章节目标。

保留必要的数据、权限与费用保护，把保存、版本、检查、恢复的协调留在系统内部。作者不用学习“编译、终态、草稿提交”等内部概念；主模型也不再反复搬运这些字段才能写完一章。正文可靠保存、检查完成和可信记忆更新分别据实记录，互不冒充。

效率和质量同时作为发布条件：减少无效读取、协议纠正、重复生成和人工干预；保持创作要求、事实边界和最终文本质量。不得靠减少要求、降低模型、缩短正文、隐藏失败或放宽安全检查取得更快的数字。

### 1.1 本次确定的产品决策

| 决策 | 4.0 的行为 |
| --- | --- |
| 创作入口 | 作者用自然语言表达目标；仅在目标或权限存在实质歧义时澄清 |
| 日常操作 | 用少量清晰读写能力完成任务；复杂能力按需出现 |
| 已有稿修改 | 先读相关原文，在原任务授权内修改；版本变化时不覆盖作者新稿 |
| 正文保存 | 由真实持久化回执确认；检查失败仍保留已保存正文 |
| 完整章节质量 | 保留必要的连续性与质量检查，集中修订后核验最终版本 |
| 可信记忆 | 只接纳经过核验且绑定来源版本的事实；未知、推测和检查失败不当作事实 |
| 运行与恢复 | 新任务逐步进入现有持久执行器；旧任务按原合同与协议恢复；保留合同不等于冻结实现缺陷，允许协议兼容修复 |
| 可见过程 | 只显示作者可理解且有用的创作信息；工具准备及时可见，不能假装已经执行 |
| 最终回复 | 按作者要求交付正文或说明剧情、修改成果，不输出内部流水账 |
| 上线完成 | 功能、数据、费用、浏览器体验和质量验收全部通过后，才标识为4.0 |

### 1.2 不在本次范围内

不重写编辑器、钱包、账号或整个平台；不新增通用 Agent 框架、微服务、工作流引擎或第二套事件系统；不默认启用更多子 Agent；不改默认模型、价格、覆盖率门槛或依赖版本；不删除历史稿件、报告、任务和失败证据；不批量激活旧暂停任务；不把公开项目整体移植进来。

后续实施沿用当前单体、领域事务、共享契约、事件和持久操作记录。新增字段或协议只有在现有结构无法表达必要事实时才增加，并说明必要性和兼容办法。

### 2.2 已确认故障应如何理解

独立复核曾使用较早章节的引文，支持紧邻前章的章末状态。原拒绝正确；界面却误报解析失败，且缺少可执行的纠正反馈。修复又发现旧事实处置丢失原始冻结输入。e48 已补来源目录、候选纠正及冻结输入保护，但浏览器验收仍待完成。S11

4.0 必须保留这几条边界：较早章不能冒充紧邻前章；计划、移动意图与推测不能证明到达或完成；旧事实处置不能清空原始义务；格式或证据定位问题不自动判成文学事实错误；拒绝后给模型的信息必须足够纠正，不能事后拿全量日志要求模型猜隐藏条件。

本轮“有纠正意图，但候选未应用，最终无进展暂停”先作为现象记录。实施前核对该调用的模型可见输入、冻结schema、候选变更、工具返回、当前正文、原复核输入及费用回执，确定是权限、定位、版本、候选协议、恢复投影或其他问题；这些是待核方向，不是预判根因。模型回放只获得当时合法可见的信息，服务器全量记录用于诊断与证明，不能作为额外隐藏提示喂给模型使样本通过。

## 4 作者体验与任务边界

### 4.1 核心场景

| 作者请求 | 系统应完成 | 不应发生 |
| --- | --- | --- |
| 问候、提问、讨论某设定 | 直接回答；需要时读取相关设定 | 强制章节目标、创建正文或进入章末流程 |
| 研究某作品或写作方法 | 查找并读取合格来源，区分样本与全书，交付有依据的结论 | 从简介猜正文；未授权顺带写稿 |
| 写下一章 | 核对真实阅读顺序和当前稿，读取承接内容，写入新目标，检查最终版本并交付 | 覆盖编辑器旧章、接管历史失败任务、完成后主动扩写下一章 |
| 改一处台词、错字或选区 | 读取目标与必要邻文，精确修改，保留范围外内容 | 例行创建场景计划、研究档案或整章重写 |
| 整章重写或连续多章 | 确认范围，分章保存，集中处理检查意见，按真实完成程度交付 | 等全部成功才保住前几章；把失败一章说成整批完成 |
| 作者边看边手改 | 以当前正文版本为准，检测冲突后读取变化处再决定 | 旧模型输出覆盖作者新稿 |
| 中断后继续 | 继续原任务缺失步骤，复用稿件、结果与已付费回执 | 把 Continue 当新授权、重写已完成章、重置消费额度 |

### 4.2 澄清与授权

先用当前对话和可访问资料解决能自行查明的问题。只有作品、目标、选区、剧情取舍或写入权限确有歧义且会改变结果时，才请求作者选择。一个问题解决当前阻碍，不把普通任务展开成审批表。

意图理解与数据权限分开：模型负责理解创作目标，服务端继续限制可写作品、对象、范围和危险操作。不得把模型推断、摘要、附件文字、旧助手承诺或子任务反馈当作新增授权。

首轮实施保留现有冻结原请求和授权校验；把不必要的章节目标要求从聊天与研究入口移除。显式“只讨论、不改稿”必须具有决定性优先级。

### 4.3 可见结果

作者已要求只要标题和正文时，从当前已保存版本交付，不重新生成一份可能不同的正文。未指定完整正文时，最终回复用简短自然语言说明本次剧情推进或具体修改；不追加“r版本、终态提交、调用次数”等内部过程。

必要限制不能隐藏：例如“第6章正文已保存。衔接检查未完成，全文已保留，暂未更新后续承接信息。”这说明实际影响，不把检查失败冒充整项任务完成。标题和正文之外的必要故障信息可由明确的结果提示承载，避免混入小说正文。

## 5 最小架构与统一执行方向

保留三个职责边界，不再叠加框架：

1. **创作能力**：意图理解、相关内容读取、写作与修改、按要求交付。
2. **可靠执行**：现有任务合同、工具权限、持久操作、取消、恢复和费用记录。
3. **派生服务**：连续性和质量检查、摘要、可信事实、人物状态及检索索引。

这是职责划分，不要求新增三套目录、服务或状态机。正文与结构写入继续走现有领域事务；检查和记忆复用现有服务与存储；前端只投影已有事实。

### 5.1 新任务的目标执行路径

以现有持久执行器为收敛方向。所有新任务都应在准入时固定执行路径，后续工具调用、等待、检查和续跑沿同一路径处理。不能因某个工具尚未适配，在任务中途切回旧副作用路径。

切换前按现有工具注册表与持久适配表逐项核对：真实可用权限、参数版本、事务副作用、联网调用、费用、取消、重复投递、结果持久化、事件展示都必须覆盖。“有适配函数”不等于该能力已满足全部运行契约。

核心读写先统一，联网研究、平台参考、结构操作、技能、导入和专业 Agent 等现有能力逐组补齐。尚未覆盖的场景继续在准入时明确使用兼容路径，不能切换后悄悄消失功能。最后一组当前支持的能力通过验证，才可称新任务统一执行完成。

### 5.2 最少状态原则

正文版本、任务状态、操作回执、检查报告和结算各自已有事实来源，继续使用。作者看到的“正在处理、已保存、需要选择、遇到问题”是这些事实的展示结果，不额外建立相互复制的一组持久状态。

不新增一套“4.0草稿→准备提交→待确认提交→已提交”的作者流程。不把所有中间结果复制成独立文稿；只保存恢复、差异、审计确有需要的版本和有限预览。

## 6 少量清晰能力与上下文

### 6.1 模型可见能力

以下是产品能力面，不要求把所有业务硬塞进一个万能工具，也不要求立即把现有接口统一改名。

| 能力面 | 默认任务需要 | 实施办法 |
| --- | --- | --- |
| 看作品与定位 | 当前作品、阅读顺序、目标与相关设定 | 复用作品上下文、目录、计划及记忆读取，合并重复摘要 |
| 读原文与查找 | 相关章、片段、选区及真实来源 | 保留分页、检索、版本及范围回执；需要整章时可便捷取全 |
| 写入或追加 | 新章、续写或明确整章覆盖 | 服务端解析目标并保存；版本、权限、快照仍生效 |
| 精确修改 | 单片段或一组相关原文替换 | 保留唯一锚点、同一原文定位、非重叠、整批原子写入 |
| 获取必要输入 | 实质歧义或创作取舍 | 复用现有提问能力，不为内部字段向作者提问 |
| 研究与扩展能力 | 明确联网、批量改动、专业检查等 | 按任务需要提供；不让普通写作默认承担全部工具说明 |

章节创建、定位和内部准备尽量由服务协调，模型仍决定标题、内容与创作意图。标题保存在独立字段；不得为简化接口把章号重复塞入正文。

保留旧工具名和冻结 schema 的兼容执行。新任务的能力说明与工具目录按任务类别在准入时确定并在任务内保持稳定；不要为每个轮次重建不同工具目录，破坏缓存和恢复身份。

### 6.2 写前上下文

写前提供一个足够而有界的上下文视图：当前原始要求、已明确的目标与限制、相关正文、紧邻前章承接、所需人物和设定、已有计划、必要待解决项。不要固定注入全书、前9章全文、所有角色卡和所有历史失败。

来源性质必须明确：原文事实、作者明确设定、已经核验的派生事实、推断或未确认记忆不能混用。全书序号与卷内序号须在定位层区分；“编辑器正在打开哪章”不等于“本任务要写哪章”。

### 6.3 执行中更新与压缩

工具结果返回当前对象、版本、实际变化和必要下一步；后续上下文以这些新事实为准。正常调用采用追加结果与局部更新，不每步重新装配全量上下文，也不重复读取已经获取且版本未变的内容。

正文或来源改变时，只失效真正依赖它的基线、报告和派生结果。修改锚点失效，就重读变化处；不能要求模型猜最新正文。无关章节变化不应触发全书重读。

先做确定性的去重、旧工具大结果压缩和版本引用，再在必要时使用现有摘要压缩。保留原始要求、明确限制、最新有效工具对、修改定位、未解决义务、来源版本和恢复引用。摘要不产生权限，压缩后无法核对的原话必须按需检索。

## 7 正文保存与复核和记忆分离

### 7.1 正文先成为可靠成果

一次授权写入在领域事务中完成所有权与范围检查、取消与有效执行者检查、当前版本比较、正文写入、必要恢复快照及持久回执。未取得数据库提交回执前，工具准备、流式正文预览与模型自述都不能称为“已保存”。

保存成功后，即使检查、摘要或人物状态提取失败，正文仍可查看、编辑和恢复。派生处理继续引用该版本；不得为让派生状态成功而恢复旧正文或清空已写内容。正文保存失败则保留已获得的模型结果到受保护的原操作记录，并说明未落入作品，不能因重新生成而付第二次费用。

已有正文的恢复快照、批量原子修改和用户编辑保护继续保留。相同内容不增加正文版本，不伪造修改进度。

### 7.2 检查不再由主模型搬运完整内部状态

主模型给出创作文本和必要的剧情判断；服务端负责绑定原请求、目标、正文版本、前章版本、检查输入和报告。场景准备、章末候选和内部提交不要求作者参与，也不应反复成为主模型补齐字段的任务。

首轮4.0保持完整章节必要的连续性与质量检查，不用“后台化”之名跳过。把同一轮相关意见集中处理，完成正文修改后对最终版本复核；不得每改一处就重跑整套检查。报告可复用的前提是正文、依赖来源、任务范围和协议均一致。

短片段修改按受影响内容检查，不机械创建完整章节流程；若修改确实改变关键事实、跨章承接，或作者要求整章审阅，则提升到相应检查范围。任务大小不能成为绕过版本或权限保护的理由。

### 7.3 检查意见的处置

事实冲突必须能指向真实正文，区分对象、人物、时间、动作方向以及计划和完成。文风、节奏和意象属于创作判断，不能仅凭形式判错。安全修法在原改稿权限内集中处理；涉及剧情改变、作者刻意风格或权限外内容时，保留具体意见和理由，必要时向作者提出真实选择。

同一版本检查失败后，向模型投影可以纠正的最小信息：问题类别、目标事实或片段、有效原文范围、当前版本与下一种合法动作。错误分类不能把证据绑定失败改称JSON解析失败；定位修正不能改写事实，有限语法修正不能补造截断的内容。

自动纠正结束后仍无法核验，就保留失败和稿件，报告具体影响；不得通过删掉难处理事实、降低严重性、改正文迎合候选或隐藏红色工具卡取得完成。

### 7.4 可信记忆与章末状态

摘要、索引与可信事实分别按现有存储约束处理。摘要可作为带来源的检索线索；未经核验的摘要不升级成可信事实。章末状态要与实际正文和真实前章绑定，核验失败时保留“未知或未确认”，不填一个看似完整的状态。

较早章节的持续事实，只能通过合法、完整的继承证据继续使用，不能冒充紧邻前章新发生的事实。冻结输入、原候选、原始响应、事实义务和输入哈希需要在纠正、替换、结束和恢复后仍可核对。

后续写章遇到上一章派生结果未完成时，可以从真实正文读取必要事实；不能自动采用失败候选。原任务若明确要求全部检查完成，仍不得把任务标成已全部完成。多章任务可保存各章成果，但传播未知状态前必须补足必要证据或如实停在依赖处。

## 8 旧任务兼容与并发保护

### 8.1 默认不做历史批量迁移

统一新任务执行不等于重写全部旧任务。旧记录继续可读、可回放；作者主动 Continue 时才准入恢复。重启不能自动重新激活所有暂停任务。

| 旧任务类别 | 处理方式 | 禁止行为 |
| --- | --- | --- |
| 已完成任务 | 按已有结果和展示兼容读取，保持历史审计 | 重新生成、补收费或把旧失败改成成功 |
| 有完整合同的普通循环暂停任务 | 保留兼容恢复路径，使用原始请求、范围、累计用量和原有恢复资格 | 仅按摘要重建任务或自动切成新协议 |
| 已有持久根与执行帧的任务 | 沿原帧、原工具授权和原结果继续；保留操作与请求身份 | 再 assembleContext、刷新技能或重置预算 |
| 等待作者选择或曾明确结束的任务 | 按原选择边界处理；已结束任务不复活 | 超时默认同意、用 Continue 擅选目标 |
| 原始请求缺失、快照损坏或来源无法核验 | 拒绝执行，保留成果，说明需要重新明确的范围 | 猜原请求、补造价格、伪造旧回执 |
| 外部请求结果或结算未知 | 先核对原操作，保留待核状态 | 重新发同一付费请求作为“恢复” |

如未来确需转换某类旧任务，只在明确的无在途操作边界实施：核验原始输入、权限、模型选择、用量、价格、正文及来源版本；保存可逆映射；原协议及回执不改。任一条件不足则继续兼容执行，不强迁。

### 8.2 模型与协议兼容

当前普通旧任务可存在作者明确选择下一次模型的行为；持久任务恢复则沿冻结配置。4.0不得悄悄改变这两类现有语义。未来新任务允许换模型时，也只影响明确安全边界之后的新请求；已派发请求、报告、价格与历史归属不可重标。

Agent产品标识4.0不等于把 `runtimeProtocolVersion` 改为4。可兼容的逻辑继续沿用当前协议；不兼容变化才增加有真实迁移与读取能力的协议版本。旧任务仍使用它自己的解析器、资源版本与证据范围，不能在恢复时自动采用新规则。

### 8.3 并发与取消

继续、新建和多窗口任务共用现有用户并发边界；正文副作用以当前有效执行者、作品、章节和版本为准。取消要传播到主模型、检查模型、联网、等待及写入前检查；旧执行者的迟到结果可保留供核对，但不能继续写稿、提交事实或擅自扣款。

同一章发生冲突时，返回当前事实并读取变化，不静默合并作者稿。多章任务按章保存，不把全部正文放进一个长事务；跨章批量修改仍走已有影响分析、预览和原子变更保护。

## 9 费用与有限恢复

费用属于可靠执行层，不要求主模型计算或传递价格。沿用已有请求身份、冻结价格、用量、预留、结算和退款记录；报告是否格式正确、检查是否通过，与供应商是否已经消费分别处理。

| 情况 | 处理原则 |
| --- | --- |
| 缓存或已保存结果可复用 | 读取原版本，避免重新联网、生成与扣费 |
| 本地等价参数修正 | 未派发前规范化；不把修正变成新的付费调用 |
| 唯一原文证据地址可确定纠正 | 在同一冻结输入内有限纠正并留痕；不能改事实或跨来源救回错误 |
| 明确瞬态失败且确定可安全重试 | 沿现有次数、时限和任务预算重试，不增设额外隐藏预算 |
| 身份、权限、额度、业务范围、乱码或受限内容失败 | 不循环重试；说明具体影响或请求必要输入 |
| 供应商是否完成未知 | 保持原请求待核，先取结果或核对；超时不是未收费证明 |
| 保存或展示失败但生成结果已保存 | 修复原结果的持久化或投影，不重新生成正文 |
| 已取消后收到结果 | 保存已知结果与用量，按原政策核对，不恢复写入权 |

所有有限恢复共享原任务剩余额度和已有保护。Continue、重准备、换窗口、换报告编号、重新选择目标都不得补充原额度。重试次数不能替代质量判断，也不能以历史累计检查次数拒绝一次有合法新版本的必要核验。

不因4.0降低默认模型或检查模型；不调整价格。若未来要改变质量配置或默认检查强度，作为明确产品变更单独验证和说明。

## 10 Search 与 Fetch 的正确性

搜索解决定位，Fetch解决实际读取，两者结果不能互相冒充。沿用已有来源、缓存、范围和网络保护，不再另造抓取系统。S17

### 10.1 读取判断

| 取得的内容 | 可做什么 | 不可做什么 |
| --- | --- | --- |
| 已核实同作品同作者的可读章节正文 | 按实际读取范围分析，绑定来源版本和字符范围 | 从样本推称全书已读 |
| 简介、目录、评论、书评、搜索摘要 | 定位作品、介绍或发现真实链接 | 分析未读正文的叙事、台词、人物细节 |
| 正常编码或格式问题，可确定还原 | 用常规确定性解码或正文抽取，保留来源和处理记录 | 猜字、用模型补正文缺口 |
| PUA、乱码、丢字或不完整正文 | 记录不可读或不完整，保留可核实元数据 | 将字符数或HTTP200当作成功、分析乱码剧情 |
| 登录、付费、验证码、访问拒绝、限流 | 明确当前限制；按原授权使用作者提供或正常可访问的材料 | 换代理、出口、托管Reader或别名绕过 |
| 供应商协议、鉴权、余额或配置错误 | 与目标站点限制区分，保留已取得材料 | 宣称原作不存在，或无依据轮换来源反复收费 |

先核作品和作者身份，再沿真实链接读取。允许替代来源时仍需核实同作品、同作者、章节和使用范围；替代站介绍页不是正版正文的替代。作者没有授予的来源选择或读取范围不能通过模型自行推断扩大。

正常公开文本的确定性编码修复与绕过内容保护有区别；无法确定是否是真实原文时按不可用处理。私有签名URL或凭据不得发给第三方Reader。

### 10.2 缓存与预算

复用本任务已经保存的正文版本，续读不重新联网。游标绑定来源版本，变更后不能跨版本拼接。导航只提供元数据，不计作正文证据；导航、失败请求和实际Fetch按现有冻结预算计数，不因换工具名或恢复任务重置。

保留既有公网URL、DNS、连接和重定向检查、大小与时间上限、取消和失败缓存。正常分页不是绕过；生成猜测URL、绕过限制或无限追加来源不是恢复。

全书研究完成需要章节清单、逐章可读正文、缺失说明和相应分析证据。仅有读取范围或若干样本，不足以宣称全书研究完成。

## 11 过程展示与交付

### 11.1 工具卡与等待动画

第一个工具参数帧到达就出现准备卡，使用同一调用身份升级为执行、完成或失败；准备阶段不是已授权执行，也不是正文保存。重连只恢复有限的最新预览，不能堆积每个正文片段的副本。

有可见正文、可见过程文本、可见思考或工具卡有效活动时，不同时显示通用等待动画；这些信道采用同一进展判断，不仅监听正文流。当前任务没有实际可见进展且仍在执行时，沿用约1.5秒静默阈值显示等待；任一可见信道恢复输出立即隐藏。工具卡已有执行活动指示时，由该卡承担当前活动展示，不叠加全局动画；仅有一张卡或旧running标签不视为持续新进展，需要等待时仍只在现有活动位置呈现一次。未展示的内部心跳和隐藏协议文本不能伪装成作者看得见的进展。

暂停、取消、等待作者、结束、切任务和事件重放均以各自真实状态处理；不得让上一个任务的输出时间抑制新任务提示，不能在历史消息上留下执行光标。沿用单个可取消计时器，避免新增轮询。此次只优化现有状态呈现，不重新设计布局，也不叠加第二套加载动画。

### 11.2 正文与过程的信息边界

创作正文逐字保持作者作品内容，不用过滤器删除小说中的代码、编号、英文、引文或JSON。操作层只展示中文功能与创作意义，内部参数、ID、原始异常和失败后自我推演留在受控诊断记录中。

优先从结构化结果生成自然展示；提示词和现有文本过滤只作兜底。失败提示保留影响、已保存成果和可采取动作，不能统一替换成没有信息的“未完成，请重试”。

### 11.3 完成判定

完成依赖原请求、实际成果和必要后置条件，不依赖模型说“完成”、待办全勾选或绿色工具卡。正文已保存与检查待完成可以同时为真；展示分别准确，任务是否全部完成则服从原始要求。

最终回复从当前真实成果生成。原文交付核对正文版本；修改总结核对实际差异；研究结论核对真实来源和范围。已完成章不因未授权的封面、发布、下一章或额外研究被重新挂起。

## 12 分阶段实施与回滚

各阶段只在前置条件满足后开始。先用离线夹具、确定性回放和隔离数据库证明正确，再做受控产品验收；不以不断付费重试代替诊断。不承诺按日历硬切，按阶段出口推进。

### P0 固定基线与关键夹具

范围：记录候选SHA、当前功能与工具清单、执行路径分布、已知产品缺陷和父级实测结果。整理原第6章早期证据失败及本轮“候选未应用→无进展暂停”的脱敏最小回放、旧暂停任务、重复请求、取消与并发夹具；引用原冻结输入，不上传用户正文。先定位实际卡点，再决定P2/P3/P4的最小相关改造，不先堆叠修补规则。

交付：一份差距清单、一份能力适配表和可重复验收样本，沿用现有研究和测试目录，不新建一套管理系统。

出口：原错误证据仍被正确拒绝；本轮失败已有准确根因、可重放夹具和明确的合法纠正预期，保留当前失败结果供P3验证；旧任务分类明确。费用或供应商未知结果保持待核，不阻塞P1及无关离线工作。P0不以尚未实施的修复通过为前提。

回滚：本阶段不改运行行为，无生产迁移。

### P1 先纠正作者可见体验

范围：去除默认总结的内部保存版本和终态句；按真实成果交付。修正工具准备卡、进展更新、等待动画、结束清理及错误影响说明。优先涉及 `writing-scope.ts`、作者展示投影、消息组件、流事件与 `useProcessingHint.ts`。

出口：正文与引文不受误过滤；作者只要标题正文时格式正确；正文、过程和可见思考三个文本信道及工具卡都纳入进展判断；解析失败与证据失败不混淆；浏览器覆盖桌面、窄屏、切任务和重连。必须重放本轮“过程持续吐字而等待动画仍在”的问题，连同内部字段泄露和结尾工具流水账一起关闭。

回滚：回退本阶段展示逻辑，不修改正文、报告、费用或历史事件。不能通过回退展示抹掉真实失败。

### P2 收敛读写能力与上下文

当前子组：持久初始化与普通循环复用同一任务工具限制，再叠加会话及目标权限；已有冻结配置不重新生成。标签复用原作品查询，相关记忆零命中时新任务不预载任意故事事实，旧回退记忆保留推断状态与来源版本。未知、混合及尚未完整建模的附加能力保持现有有效目录，不凭未识别关键词删除功能。独立复核的完整冻结证据和当前任务义务不在此裁剪。

范围：普通任务只提供必要能力和简短规则；复用安全读写实现；把重复目标定位与准备协调收进服务；建立一次写前上下文视图，执行中局部更新。主要涉及 `context.ts`、工具注册与展示、`task-spec.ts`、读写工具及现有上下文压缩。

出口：聊天和研究不强制章节；下一章定位正确；小改不启动全章流程；局部修改越界、过期或歧义仍被拒绝；相同任务输入Token与无效调用下降且正文要求不减。

回滚：只对之后新准入任务恢复原能力目录与提示；已经冻结的任务继续原目录和schema，不能在中途改工具合同。

### P3 分离正文与派生结果

范围：可靠保存回执先独立成立；检查、候选、摘要和可信事实各用原版本处理；集中修订与最终版本复核；保留失败义务和原始冻结输入。主要涉及正文领域事务、章节复核、编译服务、记忆提取和完成判定。

出口：保存后检查失败不丢稿；保存失败不谎报成功；修后旧报告失效；失败事实不进入可信记忆；重试复用生成结果且不重复收费；必要检查缺失时不宣称整项完成。

回滚：停用之后新任务的协调变化，保留已写稿与所有派生记录。不得回滚作者正文或down migration。数据库字段保持向前兼容；旧服务无法读取的新记录不能交给旧执行器。

### P4 补齐持久适配并切换新任务

当前子组：报告、计划交付、站内参考及部分创作资料共10项完成接线。Search/Fetch已补已保存供应商结果重放时的研究账本幂等补写，不新增请求、预算或收费；其完整持久适配仍需原操作身份、租约事务及未知结果矩阵，不能据此开启新任务默认切换。

范围：依据P0能力表，逐组补齐现有持久执行器，优先核心读写与检查，然后联网、平台资料和其他当前支持能力。每组验证操作输入、结果、费用、取消、事件、恢复和并发，再在准入边界切换新任务；旧任务兼容测试与切换同时交付。

先内部测试账号和受控任务，再扩大新任务范围。切换比例和观察窗口沿用现有开关能力，由实际流量及样本覆盖决定；不为灰度另建调度平台。每个任务在首次准入时固定路径，不进行双执行或双重付费。

出口：所有当前支持场景都有完整适配；未适配工具不得隐式调用旧副作用；普通新任务统一路径；旧循环与旧持久任务均按原协议恢复；冷启动、重复Continue、过期执行者和未知供应商结果全部通过真实隔离数据库验证。

回滚：停止给新任务分配有缺陷的路径；已进入新路径的任务继续由能读取其协议的兼容版本恢复或安全暂停。不能把新任务送入旧循环，不能默认认为e48二进制能恢复新记录。回退包必须先证明读取兼容，保留原回执与费用事实。

### P5 成本质量比较与真实产品验收

范围：按第14节同条件比较3.5与4.0；执行第13节验收矩阵，并完成真实浏览器产品流程。付费样本先冻结数量、模型、输入、预算和停止条件，使用已有明确授权；无授权时完成离线部分并列出剩余产品验证，不自行付费。

出口：无保护退化；核心任务完成率和创作质量不降；效率观测完整、无未经解释的明显退化；完整章节、多章、研究、修改、恢复和Search/Fetch均有实际结果证据。每个失败归类到真实根因，不隐藏失败或靠再次生成冲掉证据。

回滚：停止扩大新任务入口，按P4规则处理已准入任务。仅回退有缺陷的行为组，不重复整次部署、不删除证据。

### P6 完成发布与版本标识同步

范围：在所有必要门槛通过后，按仓库维护的精确SHA发布流程上线并核对实际健康、版本和浏览器行为。能力上线并验收后，最后以一个连贯收尾批次同步第15节文档与产品标识。若收尾修改客户端产物，按最终SHA完成仓库要求的检查、CI和受控发布；不借用旧SHA的通过状态，也不为纯标识变化重复付费写章。

出口：实现、离线验证、原始同SHA CI、部署核对、产品验收和标识同步全部完成；没有仍影响核心创作或安全的未闭合阻断项。

回滚：使用已验证兼容的回退版本和原发布入口；业务数据不倒退。应用回退不重放付费请求、不改旧协议、不回滚钱包事实。

### 12.1 开发与验证纪律

每个交付组指定一个主写入责任人；跨领域评审集中检查权限、保存、恢复和费用边界，不按每个文件重复全量评审。批量完成关联代码、契约和测试调整后再跑相应检查。

小组先运行能证明行为的相关单元与集成测试；发布候选继续保留 `check`、`lint`、完整覆盖率测试、`build`、真实PostgreSQL零跳过集成、Agent eval和生产/全量依赖审计。已有门槛不降低，源码字符串断言不能代替行为测试，DOM通过不能代替浏览器验收。

使用原始完整同SHA CI作为发布证据，不重复已经完成且未受改动影响的全量检查。任何数据库验证只使用已获准的隔离环境；不为测试重置生产或用户数据库。

## 14 效率质量与成本的量化方法

### 14.1 比较设计

建立固定的脱敏任务组，覆盖聊天设定、单处修改、较长改稿、写下一章、多章、研究、暂停恢复及工具故障。各类必须单独报告，不能用大量便宜聊天掩盖写章变慢。

离线阶段先比较确定性事件回放和桩件行为，固定样本至少覆盖24种任务与故障组合。真实付费观测合并既定原任务恢复、3个不同新章、单次5章及自然聊天、研究、修订与Search/Fetch验收；复用适用的已有基线，不额外默认进行6–8组双份A/B。冻结样本预算、模型、输入和停止条件；预算用尽时报告已有证据及具体缺口，不自动扩样，只在已有授权内补必要缺口。有限样本不宣称统计显著。

保持同原始要求、可见资料、模型与推理设置、目标篇幅、质量配置和任务预算。缓存热度、供应商异常和人工干预单列；时间记录拆为排队、模型、工具、数据库、检查和作者等待，不把暂停时间算模型执行。

### 14.2 指标定义

| 指标 | 统计口径 |
| --- | --- |
| 有效完成率 | 原请求范围与必要检查均完成的任务数 / 全部准入任务；部分完成和未知结果单列 |
| 首次成功率 | 无人工重发、无额外Continue的有效完成比例 |
| 数据保护 | 丢稿、越权写、覆盖作者新稿、未经核验事实进入可信记忆、重复消费分别计数 |
| 人工干预 | 作者为纠正目标、搬运内部字段、处理可恢复故障付出的额外操作次数 |
| 首次可见进展 | 准入到作者看到有意义文本或工具准备的时间；等待动画不算成果 |
| 首次可靠正文 | 准入到可读取的已保存正文回执；流式参数和预览不计 |
| 完整交付时长 | 准入到原任务必要后置条件完成；报告P50/P95和各阶段耗时 |
| 上下文与协议开销 | 输入/输出/缓存Token、重复读取字数、无效调用、纠正轮次及重复报告次数 |
| 成本 | 每任务和每次有效成果的用户应收/实扣/退款，与供应商现金成本分别统计；每次有效成果成本含该组失败尝试成本，未知账单单列 |
| 写作质量 | 盲评意图符合、事实连续、人物声音、表达与节奏、改稿准确性；同时记录硬错误 |
| 恢复质量 | 原结果复用率、额外生成次数、原范围保持、重复费用、恢复后最终版本一致性 |

### 14.3 发布门槛

保护性门槛为零容忍：验收中出现丢稿、越权、重复收费、旧稿覆盖、虚假完成或未核验事实污染可信记忆，均阻断发布。

核心脚本任务要求全部通过；盲评不得出现关键创作要求或事实连续性的实质退化。评分采用同量表和匿名版本的成对评阅，关键质量争议再由第二名评阅者独立复核；不把每次普通修改变成双人审批。单人评阅明确其证据强度，不能伪称多人独立评审。

效率探索目标：相同条件下，无效调用和人工干预明显减少；写章/改稿P50完整交付时间或每次有效成果总成本探索下降15%，另一项退化不超过5%，P95探索退化不超过10%。这些数字是研究目标，不能作为缺乏适用基线的硬发布门槛，也不能为了追数字无限付费实验。比较前固定统计口径，解释缓存、供应商、样本差异和长尾，不事后挑选有利结果。

P5出口是效率观测完整、没有未经解释的明显退化；数据安全、创作质量与真实完成仍为硬门槛。质量与效率冲突时先保质量，定位重复工作与上下文开销，不降模型、不删正文或必要检查。样本不足据实列出不确定性与必要缺口，不自动扩样。

### 14.4 最少观测实现

优先聚合现有任务、操作、供应商、工具、事件与费用记录；确有缺失时只补能回答具体指标的字段或阶段时间。不要记录整段用户正文、思考原文和密钥来做性能监控；正文质量评估使用获准且隔离保存的样本。

每次阶段验收留一份紧凑结果：候选SHA、环境、样本范围、模型设置、指标、失败类别、证据指针和结论。复用同一证据，不在多份文件重复复制全量日志。
